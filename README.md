# ORBIT WATCH — 第一版互動原型

本專案是一個**可直接在瀏覽器開啟的單檔 HTML 原型**，預設繁體中文、深色科技儀表板。

## 開始使用

直接開啟 `index.html`。無需安裝套件或網路連線。亦可執行 `python -m http.server 8000` 並造訪 http://localhost:8000 。

## 已完成頁面

- 首頁：全球資訊總覽、重點任務、關注清單與新聞摘要
- 發射動態：關鍵字搜尋、狀態篩選、業者篩選、任務詳情、模擬異動紀錄
- 衛星星系：搜尋、軌道篩選、星系詳情、關注與取消關注
- 產業新聞：分類及搜尋
- 私人研究監測中心：關注星系、建立／刪除筆記、匯出 JSON
- 響應式導覽與手機側欄

## 重要限制

- **所有任務、日期、新聞與統計資料皆為模擬示例，並非即時衛星發射資料。**
- 星系名稱與一般介紹用於展示，不代表已查核的最新資料。
- **沒有串接外部 API**，也沒有自動背景資料更新。
- 私人工作台只使用瀏覽器 localStorage，**沒有身份驗證、雲端存取權限或多裝置同步**。
- 切勿輸入敏感、公務或機密資料。

## v5：新聞正式資料格式（前端原型）
- 新聞標準欄位：`id`, `title`, `summary`, `category`, `published_at` (ISO 8601), `source_name`, `source_url`, `url`, `image_url`, `tags`, `constellation_ids`, `is_demo`。
- 可從新聞頁下載 JSON 格式範例並匯入；匯入資料僅保留於當前頁面，重新整理後清除。
- 對圖片採錯誤載入備援，`image_url` 需要可公開存取的圖片網址；請先確認圖片使用權限。
- `url` 與 `source_url` 限 HTTP(S)，匯入資料**尚未自動驗證來源真實性**。
- 不串接真實新聞 API，不聲稱已自動更新。

## v6 公開資料串接
網站開啟後嘗試以瀏覽器直接取得 Launch Library 2 的近期發射任務與 Spaceflight News API 的最新文章；可點「更新資料」重試。每項來源獨立失敗回退示範資料，畫面上標示資料狀態。由於純靜態 HTML 直接跨網域請求，能否成功取決於來源 CORS、網路、頻率限制及瀏覽器安全設定；真正公開部署應改用伺服器端快取、排程更新與持久化資料庫。本版無歷史異動資料儲存，也不保證新聞圖片授權，正式使用時需確認授權條件。


## v6（2026-10-16）交付說明
- 首頁、發射動態與新聞頁嘗試在瀏覽器向 Launch Library 2 和 Spaceflight News API 請求最新資料。
- 發射與新聞各自顯示來源狀態及資料更新時間；API 失敗會獨立退回示範內容，絕不偽裝為即時資料。
- 每次開啟頁面可更新，亦可手動按「更新資料」或切換示範模式。
- 此版本為無後端的靜態原型：跨域 CORS、來源頻率限制或離線環境可能導致連線失敗；此情況請使用 HTTP 靜態伺服器開啟。
- 目前未實作後端快取、週期性資料擷取、異動快照、正式資料庫、使用者登入及圖片授權管理。
- 正式公開營運前應使用伺服器端代理和快取，不宜以瀏覽器直接呼叫未有 SLA 的第三方 API。

## v6.1 軌道圖例補充欄位

首頁四個星系殼層卡片新增「累計發射衛星數」。數值由 `satelliteLaunchCounts` 集中管理。預設 `count: null`，顯示「— 待查證」；只有確認原始資料來源及統計日期後，才應填入整數 count，並填入 asOf/source。發射衛星總顆數不同於火箭發射次數及目前在軌衛星數。本版不會憑空生成即時衛星數值。

## v6.2 — 首頁發射衛星數統計快照（2026-10-16 建立）
- 在首頁四個軌道殼層卡片顯示有日期與出處的公開衛星數據。

- 發射及新聞 API 的既有讀取功能不等於上述衛星累計量能自動更新。

## v6.3 每日衛星編目快照及趨勢圖

**本版新增程式與排程，不代表 GitHub 排程已在你的帳號啟用。** 必須先將專案放在 GitHub 儲存庫，才會自動執行。每日快照儲存在 `data/satellite-history.json`，而首頁會讀取此檔顯示數量及趨勢；使用 `file://` 直接開啟時，瀏覽器可能阻擋 JSON 讀取，建議以 `python -m http.server 8000` 開啟網站。

- 排程檔：`.github/workflows/daily-satellites.yml`，每天 03:23 UTC（臺灣時間 11:23）執行，亦可由 Actions 手動執行。
- 擷取腳本：`update_satellite_history.py`，向 CelesTrak GP 的 STARLINK、KUIPER、ONEWEB 群組各發送一次 JSON 查詢，計算去重的 NORAD 編目筆數。來源失敗時不會寫入假的 0 筆數據；成功群組可個別保存。
- 指標嚴格定義為 **GP 星系群組編目紀錄數（gp_catalog_records）**，不等於累計發射衛星數、現役衛星數、實際運作數或火箭發射次數。
- v6.2 的累計發射快照保留人工查證，**不會被此排程覆寫**。O3b mPOWER 尚未找到可直接一對一對應的 CelesTrak GP 群組，因此不自行從 SES 全部衛星估算。
- 歷史資料初始為空陣列，排程執行後才開始累積，不虛構過去每日數據。每日同日再執行會更新同日紀錄，保留近 730 個日期。
- 請將此資料夾內容上傳至 GitHub 儲存庫**根目錄**；在儲存庫 Settings → Actions → General 確認 Actions 允許運行且具備寫入權限，若使用分支保護，需調整授權或改以 PR 模式更新資料。GitHub Actions 排程並非精確計時服務，可能延後。建議搭配 GitHub Pages 發布網站。
- CelesTrak 使用政策： https://celestrak.org/usage-policy.php 。請遵守資料取得頻率與再散布條件。
- 限制：由於本環境無法直接取得並確認即時 API 結果，尚未實測真實每日資料；完成上線後請先手動執行一次 workflow 確認回應格式和更新檔案。
